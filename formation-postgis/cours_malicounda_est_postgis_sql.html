Chapitre 1

Préparer la base Malicounda_EST

Séance 1 · 30 min

1.1 Ouvrir l'outil de requête

  1. Dans pgAdmin, déplier Servers > PostgreSQL 18 > Databases.
  2. Cliquer sur la base Malicounda_EST, puis Tools > Query Tool (ou clic droit > Query Tool).
  3. Vérifier en haut de l'onglet que la connexion indique bien Malicounda_EST/postgres@PostgreSQL 18.
Deux serveurs, une seule bonne base

pgAdmin affiche deux serveurs : PostgreSQL 16 (croix rouge : arrêté) et PostgreSQL 18. Toute la formation se fait sur PostgreSQL 18, dans la base Malicounda_EST, et pas dans la base postgres créée par défaut. Une requête lancée dans la mauvaise base « marche » mais crée les tables au mauvais endroit.

1.2 Activer PostGIS dans la base

Le dump QGIS utilise la fonction AddGeometryColumn, qui n'existe que si PostGIS est activé dans cette base. Cette étape vient donc avant l'import.

CREATE EXTENSION IF NOT EXISTS postgis;   -- une seule fois par base
SELECT PostGIS_Full_Version();            -- vérifier : doit afficher POSTGIS="3.x ..."

Pour exécuter : sélectionner les lignes puis appuyer sur F5 (ou le bouton ▶). Sans sélection, pgAdmin exécute tout le contenu de l'onglet.

1.3 Créer les schémas de travail

Un schéma est un dossier de tables à l'intérieur de la base. On en crée deux :

CREATE SCHEMA IF NOT EXISTS brut;   -- données telles que livrées par QGIS : on n'y touche plus
CREATE SCHEMA IF NOT EXISTS cad;    -- tables propres sur lesquelles on travaille
À retenir

Une extension s'active base par base. IF NOT EXISTS évite une erreur si l'objet existe déjà : on peut relancer le script sans crainte.

Chapitre 2

Importer le dump SQL produit par QGIS

Séance 1 · 45 min

2.1 Que contient le fichier ?

Un dump est un simple fichier texte rempli d'instructions SQL. On peut l'ouvrir dans le Bloc-notes pour le lire (sans l'enregistrer). Celui de Malicounda Est contient, dans l'ordre :

SET standard_conforming_strings = ON;
DROP TABLE IF EXISTS "public"."malicouda est" CASCADE;      -- supprime l'ancienne version
BEGIN;                                                       -- début de transaction
CREATE TABLE "public"."malicouda est"();                     -- table vide
ALTER TABLE "public"."malicouda est" ADD COLUMN "ogc_fid" SERIAL ... PRIMARY KEY;
SELECT AddGeometryColumn('public','malicouda est','wkb_geometry',32628,'MULTIPOLYGON',3);
ALTER TABLE "public"."malicouda est" ADD COLUMN "n° du lot" VARCHAR(80);
-- ... 13 autres colonnes ...
INSERT INTO "public"."malicouda est" (...) VALUES ('01060000A0747F...', '3710', ...);
-- ... 3 120 lignes INSERT, une par lot ...
CREATE INDEX "malicouda est_wkb_geometry_geom_idx" ON ... USING GIST ("wkb_geometry");
COMMIT;                                                      -- validation

Trois remarques à faire aux étudiants :

  • Le nom de la table est malicouda est : une faute de frappe (il manque le n) et un espace. On la renommera au 2.4.
  • La géométrie est en MULTIPOLYGON avec 3 dimensions (X, Y, Z = 0). Le Z est inutile pour un plan cadastral : on le retirera au chapitre 4.
  • La longue suite hexadécimale 01060000A0747F… est la géométrie codée en WKB. 747F correspond au SRID 32628.
Attention au DROP TABLE

La deuxième ligne supprime la table si elle existe déjà. Relancer le dump efface donc toutes les modifications faites directement dans public."malicouda est". C'est une raison de plus pour travailler dans une autre table (chapitre 4).

2.2 Méthode A : avec pgAdmin

  1. Dans l'outil de requête de la base Malicounda_EST, cliquer sur l'icône dossier (Open File) et choisir Malicouda_EST.sql.
  2. Le fichier (environ 2 Mo) s'affiche dans l'éditeur. Appuyer sur F5 sans rien sélectionner.
  3. Attendre le message Query returned successfully dans l'onglet Messages.
  4. Dans l'arbre, clic droit sur Schemas > public > Tables puis Refresh : la table malicouda est apparaît.

2.3 Méthode B : en ligne de commande avec psql

Plus rapide pour les gros fichiers. Ouvrir l'invite de commandes Windows dans le dossier du fichier :

chcp 65001
set PGCLIENTENCODING=UTF8
"C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d Malicounda_EST -f Malicouda_EST.sql

chcp 65001 et PGCLIENTENCODING=UTF8 évitent que les caractères « ° » et les accents soient abîmés. psql demande le mot de passe : ne jamais l'écrire dans la commande.

Un import réussi se termine par des lignes INSERT 0 1 puis CREATE INDEX et COMMIT.

2.4 Ranger la table importée

On déplace la table dans le schéma brut et on lui donne un nom sans espace ni faute :

ALTER TABLE public."malicouda est" SET SCHEMA brut;       -- change de dossier
ALTER TABLE brut."malicouda est" RENAME TO lots_qgis;     -- change de nom
Vérifier tout de suite

SELECT COUNT(*) FROM brut.lots_qgis; doit renvoyer 3120.

Les noms sont coupés à 10 caractères (nom lotiss, orientatio) : c'est la limite du format shapefile, par lequel la couche est passée dans QGIS. Ils contiennent aussi des espaces et des « ° ».

3.2 Les guillemets doubles

Un nom de colonne qui contient un espace, un accent, un symbole ou une majuscule doit être écrit entre guillemets doubles. Les guillemets simples, eux, servent aux valeurs de texte.

SELECT n° du lot FROM brut.lots_qgis;          -- ERREUR : syntax error at or near "°"
SELECT "n° du lot" FROM brut.lots_qgis;        -- correct : nom de colonne
SELECT * FROM brut.lots_qgis
WHERE "n° du lot" = '3710';                    -- "colonne"  et  'valeur'
À retenir

"…" = un nom (table, colonne). '…' = une valeur (texte, date). Pour éviter les guillemets, on donnera des noms simples à nos propres colonnes : minuscules, sans accent, mots séparés par _.

Chapitre 4

Créer la table de travail cad.parcelles

Séance 1 · 1 h

On construit une table propre : noms de colonnes simples, géométrie en 2D, chaînes vides remplacées par NULL. La table brute reste intacte et sert de référence.

4.1 Créer la structure : CREATE TABLE

CREATE TABLE cad.parcelles (
    id           INTEGER PRIMARY KEY,           -- reprend ogc_fid ; unique et obligatoire
    num_lot      VARCHAR(80),
    commune      VARCHAR(80),
    village      VARCHAR(80),
    lotissement  VARCHAR(80),
    num_dcm      VARCHAR(80),
    num_arrete   VARCHAR(80),
    nicad        VARCHAR(80),
    superficie   NUMERIC(10,0),                 -- surface déclarée en m²
    prenom       VARCHAR(80),
    nom          VARCHAR(80),
    num_cni      VARCHAR(80),
    geom         geometry(MultiPolygon, 32628)  -- 2D, UTM 28 N
);
ÉlémentSignification
INTEGERnombre entier
VARCHAR(80)texte de 80 caractères au plus
NUMERIC(10,0)nombre de 10 chiffres sans décimale
PRIMARY KEYidentifiant unique et jamais vide de chaque ligne
geometry(MultiPolygon, 32628)colonne spatiale qui n'accepte que des multipolygones 2D en EPSG:32628

4.2 Remplir à partir de la table brute : INSERT … SELECT

INSERT INTO cad.parcelles
      (id, num_lot, commune, village, lotissement, num_dcm, num_arrete,
       nicad, superficie, prenom, nom, num_cni, geom)
SELECT ogc_fid,
       NULLIF(TRIM("n° du lot"), ''),   -- espaces retirés ; texte vide -> NULL
       commune,
       village,
       "nom lotiss",
       "n ° dcm",
       "n° arrete",
       "nicad du l",
       superficie,
       NULLIF(TRIM(prenom), ''),
       NULLIF(TRIM(nom), ''),
       "n° cni",
       ST_Force2D(wkb_geometry)          -- supprime la coordonnée Z
FROM brut.lots_qgis;
  • TRIM(x) enlève les espaces au début et à la fin.
  • NULLIF(x, '') renvoie NULL si x est vide. Ainsi « pas de numéro » s'écrit toujours de la même façon.
  • ST_Force2D est indispensable : sans elle, PostgreSQL refuse d'insérer une géométrie 3D dans une colonne 2D (Column has Z dimension but geometry does not).

4.3 Index, commentaires et statistiques

CREATE INDEX idx_parcelles_geom    ON cad.parcelles USING GIST (geom);   -- index spatial
CREATE INDEX idx_parcelles_num_lot ON cad.parcelles (num_lot);          -- index classique

COMMENT ON TABLE  cad.parcelles            IS 'Lots du lotissement de Malicounda Est';
COMMENT ON COLUMN cad.parcelles.superficie IS 'Surface déclarée en m² (issue du plan)';

ANALYZE cad.parcelles;          -- met à jour les statistiques utilisées par PostgreSQL

SELECT COUNT(*) FROM cad.parcelles;   -- résultat attendu : 3120
Pourquoi un index ?

Un index est comme l'index d'un livre : au lieu de lire les 3 120 lots, PostgreSQL va directement aux bons. L'index GIST accélère toutes les recherches spatiales (ST_Intersects, ST_DWithin, ST_Touches…).

5.3 Chercher dans du texte : LIKE et ILIKE

SELECT num_lot FROM cad.parcelles WHERE num_lot LIKE 'LOT%' LIMIT 10;   -- commence par LOT
SELECT num_lot FROM cad.parcelles WHERE num_lot LIKE '%;%'  LIMIT 10;   -- contient un ;
SELECT num_lot FROM cad.parcelles WHERE num_lot ILIKE '%bis%';          -- bis, BIS, Bis...

% remplace n'importe quelle suite de caractères, _ un seul caractère. ILIKE ignore les majuscules. On découvre ainsi plusieurs façons de numéroter : 3710, LOT 11 K, 2228;2230, 4518BIS, 2934A.

5.9 Fonctions sur le texte

SELECT num_lot,
       UPPER(num_lot)                AS majuscules,
       LENGTH(num_lot)               AS longueur,
       SPLIT_PART(num_lot, ';', 1)   AS premier_numero,
       CONCAT_WS(' ', prenom, nom)   AS proprietaire     -- ignore les NULL
FROM cad.parcelles
WHERE num_lot LIKE '%;%'
LIMIT 5;
NULL contamine les calculs

prenom || ' ' || nom donne NULL dès que l'un des deux est vide. CONCAT_WS(' ', prenom, nom) ignore les valeurs absentes. De même, 300 + NULL vaut NULL.

Une trace de la jointure QGIS

Sur 26 lots, la colonne prenom contient plusieurs personnes séparées par ||. QGIS a fusionné ainsi les lignes Excel qui portaient le même numéro de lot. On les retrouve avec WHERE prenom LIKE '%||%'. Ce sont des copropriétés ou des doublons de l'Excel, à vérifier avec le service.

Chapitre 6

Modifier les données en sécurité

Séance 2 · 1 h 15

6.1 Ajouter des colonnes et les remplir : ALTER TABLE et UPDATE

ALTER TABLE cad.parcelles ADD COLUMN surface_calc NUMERIC(10,2);
UPDATE cad.parcelles SET surface_calc = ROUND(ST_Area(geom)::numeric, 2);

ALTER TABLE cad.parcelles ADD COLUMN type_numero VARCHAR(20);
UPDATE cad.parcelles
SET type_numero = CASE
      WHEN num_lot IS NULL       THEN 'absent'
      WHEN num_lot ~ '^[0-9]+$'  THEN 'numerique'      -- ~ : expression régulière
      WHEN num_lot LIKE '%;%'    THEN 'multiple'
      WHEN num_lot ILIKE 'LOT%'  THEN 'ancien (LOT)'
      ELSE                            'avec suffixe'
    END;

SELECT type_numero, COUNT(*) FROM cad.parcelles GROUP BY type_numero ORDER BY 2 DESC;

^[0-9]+$ se lit : « du début (^) à la fin ($), un ou plusieurs (+) chiffres ([0-9]) ».

6.2 La transaction : un filet de sécurité

UPDATE et DELETE sans WHERE

Ils s'appliquent à toutes les lignes. Règle : écrire d'abord le SELECT avec la même condition, regarder le résultat, puis travailler dans une transaction.

On supprime les « débris » : des polygones de moins de 1 m² hérités du nettoyage du DWG.

BEGIN;                                                       -- ouvrir la transaction
SELECT COUNT(*) FROM cad.parcelles WHERE ST_Area(geom) < 1;  -- 1. voir : 46 lignes
CREATE TABLE cad.debris AS
    SELECT * FROM cad.parcelles WHERE ST_Area(geom) < 1;     -- 2. garder une trace
DELETE FROM cad.parcelles WHERE ST_Area(geom) < 1;           -- 3. supprimer
SELECT COUNT(*) FROM cad.parcelles;                          -- 4. vérifier : 3074
COMMIT;                                                      -- valider ... ou ROLLBACK;

Tant que COMMIT n'est pas lancé, ROLLBACK annule tout. Faire l'essai : lancer les étapes 1 à 4, puis ROLLBACK, et constater que les 3 120 lots sont revenus. Recommencer ensuite avec COMMIT.

6.3 Les contraintes : faire respecter des règles

-- Un numéro de lot devrait être unique... essayons :
ALTER TABLE cad.parcelles ADD CONSTRAINT uq_num_lot UNIQUE (num_lot);
-- ERREUR : could not create unique index "uq_num_lot"
--          Key (num_lot)=(...) is duplicated.

-- Une superficie doit être positive : maintenant que les débris sont supprimés, ça passe
ALTER TABLE cad.parcelles
    ADD CONSTRAINT ck_superficie_positive CHECK (superficie > 0);

L'erreur est instructive : la base refuse une règle que les données ne respectent pas. Il faudra d'abord régler les numéros en double (chapitre 9). Le CHECK, lui, empêchera désormais toute saisie d'une superficie nulle ou négative.

Chapitre 7

Plusieurs tables : clés et jointures

Séance 3 · 1 h 15

Un même propriétaire peut avoir plusieurs lots. Répéter son nom sur chaque lot crée des risques d'incohérence (fautes de frappe différentes). On range donc les propriétaires dans leur propre table, et chaque lot pointe vers son propriétaire par un numéro : la clé étrangère.

7.1 Créer la table des propriétaires

CREATE TABLE cad.proprietaires (
    id      SERIAL PRIMARY KEY,        -- numéro automatique 1, 2, 3...
    prenom  VARCHAR(80),
    nom     VARCHAR(80) NOT NULL,      -- obligatoire
    UNIQUE (prenom, nom)               -- pas deux fois la même personne
);

INSERT INTO cad.proprietaires (prenom, nom)
SELECT DISTINCT prenom, nom
FROM cad.parcelles
WHERE nom IS NOT NULL
ORDER BY nom, prenom;

7.2 Relier chaque lot à son propriétaire

ALTER TABLE cad.parcelles
    ADD COLUMN proprietaire_id INTEGER REFERENCES cad.proprietaires (id);

UPDATE cad.parcelles p
SET proprietaire_id = pr.id
FROM cad.proprietaires pr
WHERE pr.nom = p.nom
  AND pr.prenom IS NOT DISTINCT FROM p.prenom;   -- égal, même si les deux sont NULL

SELECT COUNT(*) FROM cad.proprietaires;                                   -- 1594
SELECT COUNT(*) FROM cad.parcelles WHERE proprietaire_id IS NOT NULL;     -- 2338
REFERENCES

REFERENCES cad.proprietaires (id) garantit qu'un lot ne peut pas pointer vers un propriétaire qui n'existe pas, et qu'on ne peut pas supprimer un propriétaire qui a encore des lots.

7.3 La jointure interne : JOIN

SELECT p.num_lot, p.superficie, pr.prenom, pr.nom
FROM cad.parcelles p                                -- p : alias court
JOIN cad.proprietaires pr ON pr.id = p.proprietaire_id
ORDER BY pr.nom, pr.prenom
LIMIT 10;

JOIN ne garde que les lots qui ont un propriétaire. Les alias p et pr évitent de répéter le nom complet des tables.

7.4 La jointure externe : LEFT JOIN

SELECT pr.id, COUNT(p.id) AS nb_lots, SUM(p.superficie) AS surface_m2
FROM cad.proprietaires pr
LEFT JOIN cad.parcelles p ON p.proprietaire_id = pr.id   -- garde tous les propriétaires
GROUP BY pr.id
ORDER BY nb_lots DESC
LIMIT 5;

8.7 Reconstituer les îlots

Un îlot est un groupe de lots qui se touchent, entouré de voies. ST_ClusterDBSCAN numérote automatiquement les groupes de géométries distantes de moins de 0,5 m.

ALTER TABLE cad.parcelles ADD COLUMN ilot INTEGER;

UPDATE cad.parcelles p
SET ilot = c.ilot
FROM (
    SELECT id,
           ST_ClusterDBSCAN(geom, eps := 0.5, minpoints := 1) OVER () + 1 AS ilot
    FROM cad.parcelles
) AS c
WHERE c.id = p.id;

CREATE TABLE cad.ilots AS
SELECT ilot                               AS id,
       COUNT(*)                           AS nb_lots,
       ROUND(SUM(ST_Area(geom))::numeric) AS surface_m2,
       ST_Multi(ST_Union(geom))::geometry(MultiPolygon, 32628) AS geom   -- fusion
FROM cad.parcelles
GROUP BY ilot;

ALTER TABLE cad.ilots ADD PRIMARY KEY (id);
CREATE INDEX idx_ilots_geom ON cad.ilots USING GIST (geom);

SELECT COUNT(*) AS nb_ilots, MAX(nb_lots) AS plus_grand_ilot FROM cad.ilots;
nb_ilotsplus_grand_ilot
304123
Fonctions de fenêtre

OVER () indique une fonction de fenêtre : elle calcule une valeur pour chaque ligne en regardant l'ensemble des lignes. ST_Union, utilisée avec GROUP BY, fusionne tous les lots d'un îlot en un seul polygone.

8.8 Détecter les lots qui se chevauchent

SELECT a.num_lot AS lot_a,
       b.num_lot AS lot_b,
       ROUND(ST_Area(ST_Intersection(a.geom, b.geom))::numeric, 2) AS chevauchement_m2
FROM cad.parcelles a
JOIN cad.parcelles b ON a.id < b.id                       -- chaque paire une seule fois
                     AND ST_Overlaps(a.geom, b.geom)
                     AND ST_Area(ST_Intersection(a.geom, b.geom)) > 0.01
ORDER BY chevauchement_m2 DESC
LIMIT 10;

Les relations spatiales

Chapitre 9

Contrôle qualité

Séance 4 · 45 min

On regroupe tous les contrôles dans une vue : une requête enregistrée sous un nom, qui se recalcule à chaque lecture. UNION ALL empile les résultats de plusieurs requêtes qui ont les mêmes colonnes.

CREATE OR REPLACE VIEW cad.v_anomalies AS
SELECT ROW_NUMBER() OVER () AS gid, a.*      -- gid : clé unique pour QGIS
FROM (
SELECT id, num_lot, 'numéro absent' AS anomalie, geom
FROM cad.parcelles WHERE num_lot IS NULL
UNION ALL
SELECT id, num_lot, 'numéro en double', geom
FROM cad.parcelles
WHERE num_lot IN (SELECT num_lot FROM cad.parcelles
                  GROUP BY num_lot HAVING COUNT(*) > 1)
UNION ALL
SELECT id, num_lot, 'lot très petit (< 100 m²)', geom
FROM cad.parcelles WHERE ST_Area(geom) < 100
UNION ALL
SELECT a.id, a.num_lot, 'chevauche un autre lot', a.geom
FROM cad.parcelles a
WHERE EXISTS (SELECT 1 FROM cad.parcelles b
              WHERE b.id <> a.id
                AND ST_Overlaps(a.geom, b.geom)
                AND ST_Area(ST_Intersection(a.geom, b.geom)) > 0.01)
UNION ALL
SELECT id, num_lot, 'géométrie invalide', geom
FROM cad.parcelles WHERE NOT ST_IsValid(geom)
) AS a;

SELECT anomalie, COUNT(*) AS nombre
FROM cad.v_anomalies
GROUP BY anomalie
ORDER BY nombre DESC;

Que faire des anomalies ?

La base ne décide pas : elle signale. Les numéros en double et les chevauchements se corrigent avec le service technique, en revenant au plan approuvé. Une fois les doublons réglés, la contrainte UNIQUE (num_lot) du chapitre 6 pourra être ajoutée et protégera la base pour toujours.

10.1 Une vue de synthèse par îlot

CREATE OR REPLACE VIEW cad.v_ilots_occupation AS
SELECT i.id,
       i.nb_lots,
       COUNT(p.proprietaire_id)                            AS lots_attribues,
       ROUND(100.0 * COUNT(p.proprietaire_id) / i.nb_lots) AS taux_pct,
       i.geom
FROM cad.ilots i
JOIN cad.parcelles p ON p.ilot = i.id
GROUP BY i.id, i.nb_lots, i.geom;

SELECT CASE WHEN taux_pct = 100 THEN 'complet'
            WHEN taux_pct = 0   THEN 'vide'
            ELSE 'partiel' END AS etat,
       COUNT(*) AS nb_ilots
FROM cad.v_ilots_occupation
GROUP BY etat ORDER BY etat;

Diviser des entiers

100 * 3 / 4 donne 75, mais 3 / 4 donne 0 : la division de deux entiers est entière. Écrire 100.0 force un calcul décimal.

Étape 0

Comment travailler dans pgAdmin

Séance 1 · 15 min

Objectif de l'étape

Savoir où écrire une instruction SQL et comment l'exécuter.

  1. Dans pgAdmin, déplier Servers > PostgreSQL 18 > Databases.
  2. Cliquer sur Malicounda_EST, puis menu Tools > Query Tool.
  3. Écrire l'instruction dans la grande zone blanche.
  4. Appuyer sur F5 (ou le bouton ▶). Le résultat s'affiche en bas, dans Data Output.

Pour exécuter une seule instruction parmi plusieurs, la sélectionner à la souris avant d'appuyer sur F5.

SELECT 'Bonjour Malicounda';
?column?
Bonjour Malicounda
Trois règles d'écriture

Une instruction se termine par un point-virgule ;. Les majuscules aux mots-clés (SELECT) ne sont pas obligatoires, mais facilitent la lecture. Tout ce qui suit -- est un commentaire : PostgreSQL l'ignore.

Étape 1

Les mots de base : table, colonne, ligne, type

Séance 1 · 20 min

Objectif de l'étape

Comprendre comment une base de données range l'information.

Une base de données ressemble à un classeur Excel très strict.

ExcelPostgreSQLÀ Malicounda
le classeurla base de donnéesMalicounda_EST
une feuilleune tablela table des lots
une ligneune ligne (un enregistrement)un lot
une colonneune colonne (un champ)le numéro du lot, la superficie…
le format de cellulele type de la colonnetexte, nombre, géométrie…

Voici à quoi ressemblent trois lignes de la table des lots :

idn° du lotsuperficiegéométrie
13710300(forme du lot)
23709300(forme du lot)
32200(forme du lot)
La grande différence avec Excel

Dans Excel, on peut taper n'importe quoi dans n'importe quelle cellule. Dans PostgreSQL, chaque colonne a un type fixé à l'avance : une colonne de nombres refuse du texte. C'est ce type que l'on appelle aussi la « variable » de la colonne. Il protège la qualité des données.

Étape 2

Les types PostgreSQL : texte, nombre, date, vrai/faux

Séance 1 · 45 min

Objectif de l'étape

Connaître les cinq types les plus utiles et savoir les écrire.

TypeCe qu'il contientComment l'écrireExemple à Malicounda
INTEGERnombre entier300identifiant d'un lot : 1, 2, 3…
NUMERICnombre à virgule303.5 (point, pas virgule)superficie : 303.5 m²
VARCHAR / TEXTtexte'LOT 11 K' (guillemets simples)numéro de lot, nom
DATEdate'2014-04-24' (année-mois-jour)date d'attribution
BOOLEANvrai ou fauxTRUE / FALSElot attribué : oui/non

2.1 Essayer chaque type

On peut afficher des valeurs sans aucune table :

SELECT 300               AS entier,
       300.5             AS decimal,
       'LOT 11 K'        AS texte,
       DATE '2014-04-24' AS date_attribution,
       TRUE              AS attribue;
entierdecimaltextedate_attributionattribue
300300.5LOT 11 K2014-04-24true

AS donne un nom à la colonne du résultat.

2.2 Demander le type à PostgreSQL

SELECT pg_typeof(300), pg_typeof(300.5), pg_typeof(DATE '2014-04-24'), pg_typeof(TRUE);
pg_typeofpg_typeofpg_typeofpg_typeof
integernumericdateboolean

2.3 Calculer avec les nombres

SELECT 15 * 20  AS surface_m2,          -- un lot de 15 m sur 20 m
       7 / 2    AS division_entiere,
       7.0 / 2  AS division_decimale;
surface_m2division_entieredivision_decimale
30033.5000
Attention

7 / 2 donne 3 : entre deux entiers, la division est entière. Il suffit d'écrire 7.0 pour obtenir 3,5.

2.4 Le type protège : on n'additionne pas du texte

SELECT 'LOT 3' + 1;      -- ERREUR : invalid input syntax for type integer: "LOT 3"
NULL : l'absence de valeur

NULL veut dire « inconnu » ou « vide ». Ce n'est ni 0, ni un texte vide. Un lot sans numéro a un numéro NULL.

À vous 1. Afficher en une seule instruction : votre prénom (texte), le nombre 3120 (entier), la date du jour 2026-10-05 et la valeur FALSE. Puis afficher le type de chacune.
Voir la réponse
SELECT 'Awa' AS prenom, 3120 AS nb_lots, DATE '2026-10-05' AS aujourd_hui, FALSE AS termine;
SELECT pg_typeof('Awa'::text), pg_typeof(3120), pg_typeof(DATE '2026-10-05'), pg_typeof(FALSE);
À vous 2. Calculer la surface en m² d'un lot de 12,5 m sur 24 m, puis convertir 300 m² en hectares (1 ha = 10 000 m²).
Voir la réponse
SELECT 12.5 * 24 AS surface_m2;          -- 300.0
SELECT 300 / 10000.0 AS surface_ha;     -- 0.03 (10000.0 évite la division entière)
Étape 3

Créer sa première table

Séance 1 · 1 h

Objectif de l'étape

Créer une petite table avec les types de l'étape 2, la remplir et la lire.

3.1 Créer la table : CREATE TABLE

On décrit chaque colonne par son nom puis son type :

CREATE TABLE mes_lots (
    id                INTEGER,
    num_lot           VARCHAR(20),       -- texte de 20 caractères au plus
    superficie        NUMERIC(10,2),     -- 10 chiffres dont 2 après la virgule
    date_attribution  DATE,
    attribue          BOOLEAN
);

La table apparaît dans pgAdmin sous Schemas > public > Tables (clic droit > Refresh si besoin). Elle est vide.

Bien nommer

Pour nos propres tables et colonnes : minuscules, sans accent, sans espace, mots reliés par _. Exemple : date_attribution, et non Date d'attribution.

3.2 Ajouter des lignes : INSERT INTO

INSERT INTO mes_lots VALUES
    (1, '3710',     300,   '2014-04-24', TRUE),
    (2, '3709',     300,   NULL,         FALSE),   -- date inconnue
    (3, 'LOT 11 K', 303.5, '2017-06-14', TRUE);

Les valeurs sont données dans l'ordre des colonnes. Le message INSERT 0 3 confirme que 3 lignes ont été ajoutées.

3.3 Lire la table : SELECT

SELECT * FROM mes_lots;        -- * = toutes les colonnes
idnum_lotsuperficiedate_attributionattribue
13710300.002014-04-24true
23709300.00[null]false
3LOT 11 K303.502017-06-14true

Remarquer : 300 est devenu 300.00 car la colonne garde toujours 2 décimales.

3.4 La table refuse les mauvaises valeurs

INSERT INTO mes_lots VALUES (4, '3708', 'trois cents', NULL, FALSE);
-- ERREUR : invalid input syntax for type numeric: "trois cents"

INSERT INTO mes_lots VALUES (4, '3708', 300, '24/04/2014', FALSE);
-- ERREUR : date/time field value out of range: "24/04/2014"
À retenir

C'est exactement ce que l'on veut : grâce aux types, aucune superficie écrite en lettres ni aucune date mal formée ne peut entrer dans la base. Les dates s'écrivent 'AAAA-MM-JJ'.

À vous 3. Ajouter à mes_lots le lot n° 4518BIS (id 4), de 296 m², attribué le 5 août 2015. Puis afficher la table.
Voir la réponse
INSERT INTO mes_lots VALUES (4, '4518BIS', 296, '2015-08-05', TRUE);
SELECT * FROM mes_lots;
À vous 4. Afficher seulement le numéro et la superficie des lots attribués.
Voir la réponse
SELECT num_lot, superficie
FROM mes_lots
WHERE attribue = TRUE;
Étape 4

Activer PostGIS et découvrir les types géométriques

Séance 2 · 45 min

Objectif de l'étape

Ajouter à PostgreSQL le type « géométrie » et connaître ses formes.

4.1 Activer PostGIS (une seule fois)

PostgreSQL ne connaît pas les cartes. PostGIS est une extension qui lui apprend le type geometry. On l'active une fois dans la base :

CREATE EXTENSION IF NOT EXISTS postgis;
SELECT PostGIS_Version();          -- vérifie : affiche 3.x

4.2 Les quatre formes à connaître

Type géométriqueFormeÀ Malicounda
POINTun pointune borne, le centre d'un lot
LINESTRINGune lignel'axe d'une rue
POLYGONune surface ferméeun lot
MULTIPOLYGONune ou plusieurs surfacesles lots dans la table livrée par QGIS

4.3 Le SRID : dans quel système sont les coordonnées ?

SRIDNomUnitéExemple de coordonnées à Malicounda
32628WGS 84 / UTM zone 28 NordmètresX = 288 945 Y = 1 598 255
4326WGS 84 (GPS)degréslongitude -16.9579 latitude 14.4487

Une géométrie PostGIS, c'est donc toujours une forme + des coordonnées + un SRID. Les plans de Malicounda sont en 32628 : les mesures sont directement en mètres.

4.4 Écrire une géométrie en texte (WKT)

On écrit le nom de la forme, puis les coordonnées X Y entre parenthèses :

SELECT ST_AsText( ST_GeomFromText('POINT(288945 1598255)', 32628) );
st_astext
POINT(288945 1598255)

ST_GeomFromText(texte, srid) fabrique une géométrie. ST_AsText la réaffiche en texte lisible. Toutes les fonctions PostGIS commencent par ST_.

SELECT GeometryType( ST_GeomFromText('LINESTRING(288900 1598240, 289000 1598240)', 32628) ) AS forme,
       ST_Length(    ST_GeomFromText('LINESTRING(288900 1598240, 289000 1598240)', 32628) ) AS longueur_m;
formelongueur_m
LINESTRING100
À vous 5. Afficher le SRID du point POINT(288945 1598255) en 32628 avec la fonction ST_SRID.
Voir la réponse
SELECT ST_SRID( ST_GeomFromText('POINT(288945 1598255)', 32628) );   -- 32628
Étape 5

Dessiner un lot en SQL

Séance 2 · 30 min

Objectif de l'étape

Créer un polygone à la main, le mesurer et le situer sur la carte.

Un lot standard de Malicounda fait 15 m sur 20 m. On donne les 4 coins, et on répète le premier point à la fin pour fermer le polygone :

SELECT ST_Area(     ST_GeomFromText('POLYGON((288940 1598250, 288955 1598250, 288955 1598270, 288940 1598270, 288940 1598250))', 32628) ) AS surface_m2,
       ST_Perimeter(ST_GeomFromText('POLYGON((288940 1598250, 288955 1598250, 288955 1598270, 288940 1598270, 288940 1598250))', 32628) ) AS perimetre_m;
surface_m2perimetre_m
30070

15 × 20 = 300 m² et 2 × (15 + 20) = 70 m : PostGIS calcule en mètres parce que le SRID 32628 est en mètres.

5.1 Où est ce lot ? Passer en coordonnées GPS

SELECT ST_AsText( ST_Transform( ST_GeomFromText('POINT(288945 1598255)', 32628), 4326) );
st_astext
POINT(-16.957903 14.448734)

ST_Transform convertit les coordonnées d'un système à l'autre. Coller 14.448734, -16.957903 dans Google Maps : on est à Malicounda Est. Ce point se trouve justement dans le lot réel n° 3710, qui fait lui aussi 300 m² (étape 8).

Voir la forme dans pgAdmin

Exécuter SELECT ST_GeomFromText('…', 32628); (sans ST_AsText), puis cliquer sur l'icône en forme d'œil dans l'en-tête de la colonne du résultat : le Geometry Viewer dessine le lot.

À vous 6. Dessiner un lot de 10 m sur 30 m dont le coin bas-gauche est en (288940, 1598250), et calculer sa surface et son périmètre.
Voir la réponse
SELECT ST_Area(     ST_GeomFromText('POLYGON((288940 1598250, 288950 1598250, 288950 1598280, 288940 1598280, 288940 1598250))', 32628)) AS surface_m2,
       ST_Perimeter(ST_GeomFromText('POLYGON((288940 1598250, 288950 1598250, 288950 1598280, 288940 1598280, 288940 1598250))', 32628)) AS perimetre_m;
-- 300 m² et 80 m : même surface, forme différente
Étape 6

Donner une géométrie à sa table

Séance 2 · 30 min

Objectif de l'étape

Ajouter une colonne géométrique à mes_lots et comprendre qu'elle a, elle aussi, un type strict.

6.1 Ajouter la colonne

ALTER TABLE mes_lots ADD COLUMN geom geometry(Polygon, 32628);

Le type geometry(Polygon, 32628) veut dire : « uniquement des polygones, uniquement en UTM 28 Nord ».

6.2 Remplir la géométrie d'un lot : UPDATE

UPDATE mes_lots
SET geom = ST_GeomFromText('POLYGON((288940 1598250, 288955 1598250, 288955 1598270, 288940 1598270, 288940 1598250))', 32628)
WHERE id = 1;                       -- seulement le lot 1

SELECT id, num_lot, ST_Area(geom) AS surface_m2 FROM mes_lots;
idnum_lotsurface_m2
13710300
23709[null]
3LOT 11 K[null]
Ne jamais oublier le WHERE

Sans WHERE id = 1, tous les lots recevraient la même forme.

6.3 La colonne refuse les mauvaises géométries

UPDATE mes_lots SET geom = ST_GeomFromText('POINT(288945 1598255)', 32628) WHERE id = 2;
-- ERREUR : Geometry type (Point) does not match column type (Polygon)

UPDATE mes_lots SET geom = ST_GeomFromText('POLYGON((288940 1598250, 288955 1598250, 288955 1598270, 288940 1598270, 288940 1598250))', 4326) WHERE id = 2;
-- ERREUR : Geometry SRID (4326) does not match column SRID (32628)

Comme à l'étape 3 pour les nombres et les dates : la forme et le SRID font partie du type, et PostGIS refuse tout ce qui ne correspond pas.

À vous 7. Donner au lot 2 (3709) le polygone de l'exercice « À vous 6 », puis afficher la surface de tous les lots.
Voir la réponse
UPDATE mes_lots
SET geom = ST_GeomFromText('POLYGON((288940 1598250, 288950 1598250, 288950 1598280, 288940 1598280, 288940 1598250))', 32628)
WHERE id = 2;

SELECT id, num_lot, ST_Area(geom) AS surface_m2 FROM mes_lots;
Étape 7

Retrouver ces types dans la table de Malicounda Est

Séance 2 · 30 min

Objectif de l'étape

Ouvrir la vraie table et reconnaître le type de chacune de ses colonnes.

Si la table n'est pas encore importée

PostGIS étant maintenant activé (étape 4), ouvrir le fichier Malicouda_EST.sql dans le Query Tool (icône dossier), puis F5. La table malicouda est apparaît dans Schemas > public > Tables.

7.1 Les guillemets doubles

Le nom de cette table et de certaines colonnes contient des espaces ou le signe « ° ». Il faut alors les écrire entre guillemets doubles.

GuillemetsServent à écrireExemple
doubles " "un nom de table ou de colonne"malicouda est", "n° du lot"
simples ' 'une valeur de texte'3710'
SELECT n° du lot FROM "malicouda est";       -- ERREUR : syntax error
SELECT "n° du lot" FROM "malicouda est";     -- correct

Premières questions sur Malicounda Est

Séance 2 · 45 min

Objectif de l'étape

Utiliser ce que l'on sait déjà (SELECT, WHERE, ST_Area) sur les vrais lots.

8.1 Compter

SELECT COUNT(*) FROM "malicouda est";                         -- combien de lots ?
SELECT COUNT(*) FROM "malicouda est" WHERE superficie = 300;  -- combien de lots de 300 m² ?

SELECT ogc_fid, "n° du lot", superficie
FROM "malicouda est"
WHERE "n° du lot" = '3710';        -- numéro = texte, donc guillemets simples

8.3 Mesurer le vrai lot

SELECT "n° du lot",
       superficie,
       ROUND(ST_Area(wkb_geometry))      AS surface_calculee,
       ROUND(ST_Perimeter(wkb_geometry)) AS perimetre
FROM "malicouda est"
WHERE "n° du lot" = '3710';
n° du lotsuperficiesurface_calculeeperimetre
371030030070

Mêmes résultats que le lot dessiné à la main à l'étape 5 : le lot 3710 est bien un lot standard de 15 m × 20 m. La colonne superficie (saisie) et ST_Area (calculée sur la forme) concordent.

À vous 8. Combien de lots font plus de 1 000 m² ?
Voir la réponse

À vous 9. Combien de lots n'ont pas de numéro ? (indice : on ne teste pas NULL avec = mais avec IS NULL)
Voir la réponse
SELECT COUNT(*) FROM "malicouda est" WHERE "n° du lot" IS NULL;   -- 257
À vous 10. Afficher la forme du lot 3709 en texte lisible.
